# زولك AI 🇸🇩

مساعد ذكاء اصطناعي سوداني بواجهة عربية متجاوبة، حسابات مستخدمين، سجل محادثات مستقل لكل مستخدم، رصيد استخدام، ولوحة إدارة.

## التقنية والبنية

- **Backend:** Python + Flask.
- **Database في الإنتاج:** PostgreSQL عبر Supabase Transaction Pooler.
- **Database محلياً والاختبارات:** SQLite.
- **AI:** Google Gemini عبر حزمة `google-genai`.
- **Hosting:** Vercel (Flask Python Function).
- **PWA:** يمكن تثبيت الموقع كتطبيق من المتصفح على الهاتف.

لا تستخدم SQLite كقاعدة بيانات دائمة على Vercel؛ ملفات نظام النشر ليست مخزناً دائماً. في الإنتاج يجب ضبط `DATABASE_URL` على رابط Supabase Transaction Pooler.

## متغيرات البيئة

اضبط القيم السرية مباشرة في إعدادات الاستضافة، ولا تضعها في GitHub أو ترسلها في المحادثات.

| المتغير | مطلوب؟ | الاستخدام |
|---|---|---|
| `DATABASE_URL` | نعم في Vercel | رابط PostgreSQL من Supabase Transaction Pooler |
| `SECRET_KEY` | موصى به بشدة | مفتاح Flask ثابت وعشوائي لتوقيع الجلسات |
| `GEMINI_API_KEY` | نعم لردود AI | مفتاح Google AI Studio |
| `ADMIN_EMAIL` | اختياري | البريد الذي ينشأ/يحدّث كحساب مدير |
| `ADMIN_PASSWORD` | اختياري | كلمة مرور المدير عند الإنشاء أو التحديث؛ لا تضعها في ملفات المشروع |
| `ADMIN_NAME` | اختياري | الاسم الظاهر للمدير |
| `COOKIE_SECURE` | اختياري | اتركه `true` في الإنتاج عبر HTTPS |
| `DATABASE_PATH` | محلي فقط | مسار ملف SQLite للتطوير والاختبارات |

### إعداد Supabase

1. أنشئ مشروع PostgreSQL في Supabase.
2. افتح Connect واختر Transaction Pooler.
3. أضف رابط الاتصال إلى Vercel باسم `DATABASE_URL`.
4. تأكد من أن كلمة مرور قاعدة البيانات مضبوطة في الرابط، ولا تشاركها علناً.

### إعداد Gemini

1. أنشئ مفتاحاً من Google AI Studio.
2. أضفه في Vercel باسم `GEMINI_API_KEY`.
3. لا تضع المفتاح في ملفات HTML أو JavaScript أو GitHub.
4. يمكن اختبار الاتصال من لوحة المدير عبر قسم فحص النظام.

## التشغيل المحلي

يتطلب Python 3.11 أو أحدث:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export SECRET_KEY="replace-with-a-long-random-secret"
export DATABASE_PATH="./zolak-local.db"
python app.py
```

على Windows فعّل البيئة الافتراضية من `.venv\\Scripts\\activate` واستخدم `set` أو متغيرات بيئة النظام بدلاً من `export`.

## الاختبارات

يعمل GitHub Actions على فحص صياغة Python وJavaScript وملف manifest، ثم يختبر:

- فتح الصفحة الرئيسية وملفات PWA.
- التسجيل والجلسات وتسجيل الدخول.
- عزل صلاحيات المدير عن المستخدم العادي دون تسجيل خروجه.
- إنشاء المحادثات وفتحها وحذفها وحفظ سجل الرسائل.
- رد AI تجريبي بمحاكاة Gemini دون استخدام مفتاح حقيقي أو استهلاك رصيد.
- إعدادات المدير، النسخ الاحتياطي، إدارة الأرصدة والحظر والحذف.

## النشر

المستودع مربوط بمشروع Vercel؛ الدمج إلى فرع `main` ينشئ نشر الإنتاج تلقائياً. بعد كل نشر افحص:

- `/health` لاتصال التطبيق بقاعدة البيانات.
- الصفحة الرئيسية وملفات CSS وJavaScript.
- سجل أخطاء Vercel.
- تسجيل الدخول ورد AI الفعلي من حساب مستخدم.

نجاح البناء وحده لا يثبت أن مفتاح Gemini صالح؛ استخدم اختبار AI من لوحة المدير.

## الأمان والنسخ الاحتياطي

- لا تحفظ كلمات المرور أو مفاتيح API في الكود أو النسخ الاحتياطية.
- كلمات مرور المستخدمين تُحفظ بصيغة hash.
- صلاحيات الإدارة تُتحقق من قاعدة البيانات في كل طلب إداري.
- النسخ الاحتياطي يتضمن المستخدمين (دون كلمات المرور)، المحادثات، الرسائل، والإعدادات.
- احتفظ بنسخة احتياطية خارج الاستضافة واختبر إمكانية استعادتها قبل الاعتماد عليها.

## التطبيق على الهاتف

الموقع يدعم التثبيت كتطبيق PWA. أي تحديث للواجهة المنشور على الموقع يظهر في نسخة PWA بعد تحديث ملفاتها ومسح ذاكرة التخزين القديمة تلقائياً بواسطة Service Worker. بناء APK/AAB الأصلي منفصل عن نشر الموقع ويجب اختبار ملف Android الناتج قبل توزيعه.
